# Local-only static PWA template

A starting point for a mobile-first web app with **no server and no accounts**.
Everything the user does stays on their device. The site is static files
under `public/`, deployed as-is. There is no build step and no backend.

## The data promise

- All user state lives on the device: `localStorage` for small values
  (via `public/local-state.js`), IndexedDB if you ever need blobs.
- Sharing between devices uses the **URL fragment** (`#s=1.…`), which
  browsers never send to any server (`public/share-link.js`).
- The app makes no network request except for its own static files.

State this promise to your users in your own words. It's the point.

## Day one checklist

1. Edit `template.config.json`. Then make `public/index.html` (title,
   `apple-mobile-web-app-title`, the `window.APP` block) and both manifests
   agree with it. `npm test` fails until they do.
2. Replace `public/icons/icon.svg` and `icon-stage.svg`, run
   `./build/make-icons.sh` (macOS) to regenerate the PNGs.
3. Replace the placeholder cards in `index.html` and the counter in `app.js`
   with your app. Keep the blocks marked as generic; they're the machinery.
4. Bump `CACHE` in `public/service-worker.js` and update its `CORE` list
   whenever the set of core files changes.
5. Create two Vercel projects (production and staging) under your account
   and name them in `template.config.json`. Run `vercel link` once in the
   repo root for the production project.

## Run locally

```bash
npm test          # unit tests + config consistency
npm run serve     # http://localhost:8000
```

## Ship a change (staging → production)

```bash
npm run deploy:staging   # rebadged copy → your staging project
# test on a real phone
npm run deploy:prod      # stamp + vercel deploy --prod from the repo root
```

Every release appends an entry to `public/app-changes.json` **in the same
commit** so users see what changed under Settings → What's new.

Details and gotchas: `docs/ship-runbook.md`.

## Layout

```
public/            the whole app, served as-is
  index.html       page shell; declares window.APP; pre-paint theme; boot guard
  app.js           generic behaviors + placeholder content
  local-state.js   storage wrappers (prefixed keys, never throw)
  share-link.js    state ⇄ URL fragment
  nav-glow.js      navigation feedback veil
  service-worker.js  offline: cache-first shell, network-first data
  app-changes.json what's-new feed
  icons/           icon.svg + PNGs; stage/ carries the STAGE ribbon
build/             deploy-staging.sh, make-icons.sh
tests/             node:test
docs/              ship-runbook.md
.claude/skills/    ship-change skill for Claude sessions
```

## Gotchas

- **Vercel Hobby plan silently blocks** deploys whose HEAD commit author it
  doesn't recognize: the CLI hangs at "Building…". Commit with the git
  identity that matches your Vercel account.
- There is **no git integration** by default. Pushing to `main` deploys
  nothing; deploys are CLI-only unless you connect the repo in Vercel.
- `public/build.json` is generated by `npm run stamp` and gitignored. The
  service worker re-registers per build number, so always stamp before a
  deploy (the deploy scripts do).
